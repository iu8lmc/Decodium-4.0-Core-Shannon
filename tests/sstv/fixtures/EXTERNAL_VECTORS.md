# Optional independent SSTV WAV vectors

The ordinary repository tests do not download or generate large media.  A
developer can nevertheless run the decoder against the pinned external pack
described here by configuring:

```text
-DDECODIUM_SSTV_EXTERNAL_VECTOR_DIR=/absolute/path/to/vector-pack
```

This adds `test_sstv_external_vectors`.  The test checks the canonical path,
regular-file status, bounded size and exact SHA-256 of every input before the
native WAV replay controller feeds it through the same Decodium RX runtime.
It then requires valid VIS mapping, a complete image with the expected mode
and geometry, no queue loss or processing failure, and at least 18 dB PSNR
against the pinned source image.  The vectors are not generated by any
Decodium encoder or decoder.

## Pinned PySSTV pack

Source project: `dnet/pySSTV`, commit
`d998fad154d3e6ad2d73af5add49beec0d2ab59f`.  PySSTV and its test asset are
MIT-licensed; retain its `LICENSE.txt` when redistributing a vector pack.
Python and Pillow are development-only vector-generation tools.  Neither is a
Decodium build, test-run, packaging or production runtime dependency.

The pack used for the recorded local interoperability run contains:

| File | Purpose | SHA-256 |
|---|---|---|
| `pysstv-source-320x256.png` | upstream PySSTV source image | `dc9668e65fc38a2db7ad3a703287ffd16077bb1015c8118e06ca46204235e2e0` |
| `pysstv-robot36-12000.wav` | Robot 36 colour, PCM16 mono 12 kHz | `6d5164a9294cbc597a7ef6494efea15a02d5a6267662e5ff98023acbed4bf0cb` |
| `pysstv-robot8bw-12000.wav` | Robot 8 monochrome, PCM16 mono 12 kHz | `660d52ca4427d4d3271281285336bc3feb86559615b005066667c4dc233ecaf0` |
| `pysstv-martinm2-12000.wav` | Martin M2, PCM16 mono 12 kHz | `4cad290aec3ee249541bcd56c85717263e3d03af18755d806d5e4418085152d5` |

The recorded generator environment was Python 3.10.3 and Pillow 12.3.0.  The
PySSTV dither source is made deterministic with `random.seed(0)` before each
mode instance.  Starting in a checkout of the pinned commit, the essential
generation operations are:

```text
random.seed(0)
image = Image.open("pysstv/tests/assets/320x256.png")
Robot36(image.resize((320, 240)), 12000, 16).write_wav(...)

random.seed(0)
Robot8BW(image.resize((160, 120)), 12000, 16).write_wav(...)

random.seed(0)
MartinM2(image.resize((160, 256)), 12000, 16).write_wav(...)
```

Imports are `PIL.Image`, `pysstv.color.Robot36`,
`pysstv.grayscale.Robot8BW` and `pysstv.color.MartinM2`.  Copy the unchanged
source PNG into the pack, verify the four hashes above, configure the absolute
pack path, build `test_sstv_external_vectors`, and execute it directly or with
CTest label `external-fixture`.

PySSTV emits Martin M2 from 160 effective horizontal samples.  The Decodium
registry deliberately keeps that effective resolution separate from the
documented 320-column wire/display raster, so the replay assertion expects a
320x256 snapshot after native horizontal expansion.

## Recorded native replay

On 2026-08-24 the pinned pack passed the production WAV replay/RX runtime on
macOS Apple Silicon with Qt 6.11: Robot 36 completed at 320x240 and 18.024 dB
PSNR, Robot B/W 8 at 160x120 and 18.661 dB, and Martin M2 at 320x256 and
24.250 dB.  Every row had valid mapped VIS, coverage 1.0, zero ingress drops
and zero processing failures.  Robot B/W 8 exercises PySSTV's 7 ms sync plus
60 ms scan compatibility profile; native TX retains the canonical 10+56 ms
profile.  The exact command was:

```text
ctest --test-dir /tmp/decodium-hamdrm.csmxg7 \
  -R '^test_sstv_external_vectors$' --output-on-failure -V
```

## Evidence boundary

Passing this optional test is independent encoder-to-native-decoder evidence
for three common analogue modes.  It is not evidence of RF, sound-card,
another application's receive path, multipath performance, Windows/Linux
execution, or HAMDRM interoperability.  Those claims require their own
recorded runs and remain separate in `docs/sstv/MODE_MATRIX.md`.
