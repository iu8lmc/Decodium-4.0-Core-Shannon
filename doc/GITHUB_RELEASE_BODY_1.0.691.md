# Decodium 4 v1.0.691

## English (British)

Decodium 4 v1.0.691 consolidates the work delivered from v1.0.685 through v1.0.690 and adds a portability fix required to build and start the current cross-platform codebase reliably.

### v1.0.685 — CAT, CW and audio foundations

- Improved CAT, CW and audio handling across the radio-control paths.
- Hardened the CW transmit and keyer workflow, including serial-keyer and audio-tone paths.
- Continued the separation between radio CAT control, local sidetone and audio-device routing.

### v1.0.686 — SSB window and asynchronous voice

- Added the resizable SSB window with a clearer two-column layout.
- Moved local voice synthesis and preview work off the UI thread so the interface remains responsive.
- Activated the updated QML translation catalogues and language handling.

### v1.0.687 — CAT recovery, guided setup and LiveMap/roster improvements

- Added an optional decode-provenance column in Full Spectrum and Signal RX. It is disabled by default for new installations and can be enabled from Setup > Decode.
- Added readable Audio/CAT diagnostics and non-destructive recovery for audio defaults and CAT reconnection.
- Preserved CAT audio devices and channels in radio profiles and refreshed device telemetry after sleep/wake.
- Protected CW sidetone tests from overlapping requests and synchronous audio-worker waits.
- Improved first-run radio detection so an already connected CAT session is not reported as “no radio detected”.
- Added a one-shot graphics reset for the next launch; it does not force a graphics backend on every subsequent launch.
- Added LiveMap and roster filters for New DXCC, New on band and New on band + mode.
- Added persistent provider/spotter ignoring, visible source information and direct filtered logbook access for grid/VUCC entities.

### v1.0.688 — fork release and macOS CI compatibility

- Published the fork release based on the integrated v1.0.687 codebase.
- Kept the macOS release workflows compatible with Qt 6.11, where bundled third-party QCustomPlot headers emit deprecated pragma diagnostics.
- Treated those third-party compatibility diagnostics separately from application warnings while retaining strict project warnings.

### v1.0.689 — DecoPort and low-end performance

- Added DecoPort radio sharing so several programs can use one physical radio through the radio's CAT protocol.
- Added radio identity detection, virtual COM-port support on Windows and the bundled com0com provenance/licensing files.
- Added the Hamlib 4.7-based radio library used by the sharing layer.
- Added the low-end PC quality mode and stopped the hidden RTTY tuning scope from redrawing.
- Added optional GUI CPU metrics through `DECODIUM_GUI_METRICS=1`.

### v1.0.690 — direct CAT Power On/Off and port recovery

- Fixed the Power On availability check in the dashboard and SSB window.
- Reopened the CAT session for the wake-up sequence after a radio is powered off through direct USB/serial CAT.
- Prevented CAT shutdown from terminating the rig thread before the serial port is released.
- Skipped unnecessary PTT-off retries when the radio is already powered off through CAT.
- Released the serial port after a failed rig open so the next connection attempt can succeed.
- Followed a radio to its new COM number when Windows renumbers the same physical device after a power cycle, without guessing when multiple candidates exist.

### v1.0.691 — portable build and startup fix

- Fixed a macOS/Linux build failure caused by Windows-only DecoPort timeout constants being compiled as unused variables under `-Werror`.
- Kept the timeout constants and the virtual-port behaviour available on Windows while excluding only the Windows-specific declarations from non-Windows builds.
- Verified the corrected macOS build and launched the resulting v1.0.691 application through Qt Quick, Metal, QML, the database, CAT bridge and decoder initialisation.
- The change is deliberately platform-guarded and does not add operating-system-specific behaviour to macOS or Linux.

### Validation and artefacts

- CMake/Ninja build completed for the local macOS arm64 configuration.
- Runtime startup was observed after the build, including the Qt Quick event loop and main QML window.
- The release workflows provide the Windows x64 installer, macOS Apple Silicon DMGs, macOS Intel DMGs, Linux x86_64 AppImage and Linux aarch64 AppImage, with checksum files where generated by the workflow.

## Italiano

Decodium 4 v1.0.691 raccoglie il lavoro rilasciato dalla v1.0.685 alla v1.0.690 e aggiunge una correzione di portabilità necessaria per compilare e avviare in modo affidabile il codice multipiattaforma corrente.

### v1.0.685 — basi CAT, CW e audio

- Migliorata la gestione CAT, CW e audio nei percorsi di controllo della radio.
- Reso più robusto il flusso di trasmissione CW e del keyer, compresi i percorsi con manipolatore seriale e tono audio.
- Mantenuta la separazione tra controllo CAT della radio, sidetone locale e instradamento delle periferiche audio.

### v1.0.686 — finestra SSB e voce asincrona

- Aggiunta la finestra SSB ridimensionabile con disposizione a due colonne più chiara.
- Spostate sintesi vocale locale e anteprima fuori dal thread dell'interfaccia, per evitare blocchi della UI.
- Attivati i cataloghi QML aggiornati e la gestione delle lingue.

### v1.0.687 — recupero CAT, configurazione guidata e LiveMap/roster

- Aggiunta la colonna opzionale della provenienza dei decode in Full Spectrum e Signal RX. È disattiva di default nelle nuove installazioni e si abilita da Setup > Decode.
- Aggiunti diagnostica Audio/CAT leggibile e recupero non distruttivo dei default audio e della connessione CAT.
- Per i profili radio vengono conservati periferiche e canali audio, con aggiornamento della telemetria dopo sleep/wake.
- Protetti i test del sidetone CW da richieste sovrapposte e attese sincrone sul worker audio.
- Migliorato il primo rilevamento della radio: una sessione CAT già connessa non viene più indicata come “radio non rilevata”.
- Aggiunto il reset grafico one-shot al prossimo avvio, senza forzare un backend grafico a ogni avvio successivo.
- Aggiunti a LiveMap e roster i filtri New DXCC, New on band e New on band + mode.
- Aggiunti ignoramento persistente del provider/spotter, sorgente visibile e apertura diretta del logbook filtrato per griglia/entità VUCC.

### v1.0.688 — release del fork e compatibilità CI macOS

- Pubblicata la release del fork basata sul codice integrato nella v1.0.687.
- Resi compatibili i workflow macOS con Qt 6.11, i cui header QCustomPlot di terze parti generano diagnostica per pragma deprecati.
- Separate le diagnostiche di compatibilità di terze parti dai warning dell'applicazione, mantenendo gli avvisi del progetto in modalità strict.

### v1.0.689 — DecoPort e prestazioni sui PC meno potenti

- Aggiunto DecoPort per condividere una radio fisica tra più programmi tramite il protocollo CAT della radio.
- Aggiunti rilevamento dell'identità radio, supporto alle porte COM virtuali su Windows e file di provenienza/licenza di com0com.
- Aggiunta la libreria radio basata su Hamlib 4.7 usata dal livello di condivisione.
- Aggiunta la modalità qualità per PC lento e fermato il ridisegno dello scope RTTY quando nascosto.
- Aggiunte metriche CPU GUI facoltative tramite `DECODIUM_GUI_METRICS=1`.

### v1.0.690 — Power On/Off CAT diretto e recupero delle porte

- Corretto il controllo di disponibilità del pulsante Power On nella dashboard e nella finestra SSB.
- Dopo lo spegnimento via CAT diretto USB/seriale, la sessione CAT viene riaperta per inviare correttamente la sequenza di risveglio.
- Evitata la terminazione del thread CAT prima del rilascio della porta seriale.
- Saltati i tentativi PTT-off non necessari quando la radio è già spenta via CAT.
- Rilasciata la porta seriale dopo un'apertura rig fallita, così il tentativo successivo può riuscire.
- Seguita la radio quando Windows assegna un nuovo numero COM allo stesso dispositivo dopo un ciclo di alimentazione; in caso di più candidati Decodium non fa supposizioni.

### v1.0.691 — correzione di build e avvio multipiattaforma

- Corretta una failure di compilazione su macOS/Linux causata da due costanti di timeout DecoPort specifiche di Windows, considerate inutilizzate con `-Werror`.
- Conservati timeout e comportamento delle porte virtuali su Windows, escludendo dai sistemi non Windows solo le dichiarazioni specifiche inutilizzate.
- Verificata la build macOS corretta e avviata l'applicazione risultante attraverso Qt Quick, Metal, QML, database, bridge CAT e inizializzazione del decoder.
- La modifica è protetta per piattaforma e non introduce comportamenti specifici di macOS o Linux.

### Verifiche e artefatti

- Build CMake/Ninja completata per la configurazione locale macOS arm64.
- Avvio runtime osservato dopo la build, compresi event loop Qt Quick e finestra principale QML.
- I workflow di release producono installer Windows x64, DMG macOS Apple Silicon, DMG macOS Intel, AppImage Linux x86_64 e AppImage Linux aarch64, con i file checksum quando previsti dal workflow.
