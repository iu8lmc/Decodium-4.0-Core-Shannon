# Native SSTV Studio and transmit path

Status: implemented local operator workflow; no live-radio interoperability
claim, 2026-08-24.

## Operator workflow

The Transmit Studio keeps three immutable images separate:

1. the local, pasted, Gallery, remote-handoff or generated source;
2. the exact selected-mode prepared raster used by WAV and live TX;
3. the image produced by the internal native encoder-to-decoder loopback.

The preparation panel exposes a normalised source crop, fit, fill/crop and
explicit stretch, rotation, flip, aspect lock, exposure, brightness, contrast,
gamma, saturation, independent RGB white balance, sharpness,
grayscale/dither, transparency background and a border. The exact preview is
always regenerated by `SstvImagePreprocessor` at the selected mode's
transmitted dimensions; QML never approximates the prepared pixels.

Eight typed overlays are available: callsign, grid, current UTC, frequency,
mode, custom text, signal report and watermark. Anchor, font pixel size and
margin are explicit and bounded. The preprocessor also caps overlay count,
text/font length, padding, opacity and rendered geometry, and elides text that
cannot fit the selected frame.

Named templates persist only the selected mode and allow-listed preparation
controls under `SSTV/StudioTemplates` in ordinary `QSettings`. They contain no
source path, audio-device identifier, CAT endpoint, credential or diagnostic
payload. Names, per-template JSON and the whole catalogue are bounded; schema
1 reads a maximum of 32 entries. The schema-0 name-to-controls map is migrated
only after every entry passes current validation. Saving an existing name
edits it; delete is explicit.

## Image decode boundary

User-selected files are decoded by content, not suffix. Before allocating the
image, the Studio rejects missing/non-regular/symlink files, empty or larger
than 64 MiB compressed content, animations or multiple frames, dimensions
above 8192 or 8,388,608 pixels, estimated decode allocation above 64 MiB, and
oversized textual metadata. The process-wide Qt image-reader allocation limit
is tightened to 64 MiB if it was not already stricter. Decoded dimensions and
`QImage::sizeInBytes()` are checked again. Decode remains an asynchronous
Studio worker operation; no file or codec work occurs in an audio callback.

## Live audio and calibration

All analogue modes use `SstvTxSourceBuilder`, `SstvTxAudioDevice` and
`SstvTxCoordinator`. The coordinator remains the only owner of Decodium's
SoundOutput lease and CAT/PTT lifecycle. It applies preflight, SWR policy,
configured output-device pinning, PTT confirmation, lead/tail delays, watchdog,
cancel, audio-loss handling and confirmed release.

The four short operator references are native phase-continuous pull sources:

| ID | Frequency | Meaning |
| --- | ---: | --- |
| `sync-1200` | 1200 Hz | sync reference |
| `black-1500` | 1500 Hz | black reference |
| `leader-1900` | 1900 Hz | leader/reference centre |
| `white-2300` | 2300 Hz | white reference |

The Bridge submits a two-second reference through
`SstvTxCoordinator::startPrepared()`. It is not a direct audio or tune
shortcut. The ordinary `cancelSstvTx()` action cancels it and the same CAT/PTT
watchdog releases the radio. The UI displays the selected Decodium audio
output, CAT rig, configured output attenuation, pending/confirmed PTT and the
coordinator's real PCM peak, nominal headroom and clipped-frame count. These
diagnostics contain scalar values only, never device IDs or paths.

The coordinator records only low-rate structured `sstv.tx` lifecycle events:
accepted/rejected start, cancellation, completion and failure, with distinct
calibration event names. Fields pass the central diagnostic allowlist and are
limited to mode ID, state, success, numeric error code and duration. Error
detail, callsign, overlay text, audio-device/CAT identity and image data are
never submitted. There are no per-pull, sample or progress events.

## Internal loopback

`SstvStudioController::startLoopback()` snapshots the prepared raster and runs
outside the GUI thread. It builds the real 12 kHz native pull encoder, feeds
bounded PCM chunks through a replay route on a real `SstvRxRuntime`, waits for
each bounded ingress chunk, and publishes only the receiver's completed
`SstvImageSnapshot`. A 512-sample zero tail closes the receiver's final
analysis window and is not counted as protocol audio. The implementation does
not copy prepared pixels into the result or inspect decoder private state.

The result is an immutable image-provider snapshot plus bounded scalar metrics:
mode, sample rate, encoded samples, chunk count, dimensions, coverage, PCM
peak, clipped samples, DSP blocks and elapsed milliseconds. Cancellation is an
atomic request observed between bounded pulls and waits. Runtime shutdown is
joined on the loopback worker; no hardware output, CAT or PTT is used.

This loopback proves internal encoder/runtime consistency and is useful for
operator diagnostics. It is self-generated evidence, not proof of reception by
another application, sound-card calibration, RF quality or real-radio PTT.
Loopback start/reject/cancel/complete/fail events use the same `sstv.tx` ring
and contain only fixed reason codes, mode ID, success and elapsed duration.

## Verification and remaining evidence

Deterministic tests cover preprocessing controls and overlays, template
save/edit/delete/limits/schema migration and rejected path fields, four exact
tone frequencies and chunk invariance, audio peak/clipping accounting,
prepared-source PTT/cancel mock lifecycle, full Robot 12 and AVT24 Studio
loopbacks, cancellation, QML control action and offscreen rendering.
The same tests inspect structured event categories/names/fields and inject
path-like error text to prove it is absent from the bounded diagnostic ring.

No live radio, physical sound output, calibrated level meter, another SSTV
application, Windows/Linux rendered page or packaged release was exercised by
this local implementation. Those remain release evidence gates.
