# Decodium 4 FT2 1.0.386

Changes from `1.0.385` to `1.0.386`.

## English

### FT8 decode engine

- Raised the shared FT decode thread ceiling from `8` to `24` across FT8, FT4 and FT2 workers.
- The automatic FT thread calculation can now use all available logical cores up to the new `24` thread ceiling, while still dropping to one thread under severe CPU pressure.
- Added OpenMP linking support on macOS through Homebrew `libomp` when available, so the higher decode thread setting is effective on Apple Silicon as well as Windows and Linux.
- Extended the in-process legacy decode request path so FT8, FT4 and FT2 embedded decodes receive the configured thread count instead of silently falling back to one worker.
- Added FT8 Stage4 decode options plumbing for low-threshold, subpass, cycle count, RX-frequency sensitivity and candidate thinning. Live decode currently keeps the stable baseline profile while the offline/test path can exercise the expanded Stage4 strategies.
- Improved crowded-band FT8 handling with supplemental Stage4 passes, focused rescue windows, overlap-aware focus selection and stricter duplicate/near-frequency merge handling.
- Added alternate FT8 bit-metric paths, including tone-power equalisation and reverse metric evaluation, to recover additional weak or overlapped candidates during deep Stage4 tests.
- Added LDPC max-iteration control to the FT8 test harness and restored decoder options after each live decode call to avoid state leakage between slots.

### RX recording and diagnostics

- RX WAV recording now receives PCM samples from the legacy audio feed as well as the normal spectrum path, so automated receive recordings are usable even when the spectrum feed is disabled.
- Added environment-controlled RX recording automation for reproducible comparisons:
  - `DECODIUM_RX_RECORD_SECONDS`
  - `DECODIUM_RX_RECORD_START_DELAY_MS`
  - `DECODIUM_RX_RECORD_ALIGN_PERIOD_MS`
  - `DECODIUM_RX_RECORD_QUIT`
  - `DECODIUM_RX_RECORD_QUIT_DELAY_MS`
- Expanded FT8 decode metrics to report effective and requested threshold/subpass/cycle settings alongside requested and active thread counts.

### Test tooling

- Extended `ft8_stage_compare` with controls for decode options, supplemental passes, candidate thinning and LDPC iterations.
- Verified locally with:
  - `cmake --build /Users/salvo/Desktop/Decodium4-build --parallel 4 --target decodium_qml`
  - `cmake --build /Users/salvo/Desktop/Decodium4-build --parallel 4 --target ft8_stage_compare`
  - Stage4 deep decode check on the crowded `20260608_014615.wav` comparison slot.

## Italiano

### Decoder FT8

- Aumentato il limite comune dei thread di decode da `8` a `24` per FT8, FT4 e FT2.
- Il calcolo automatico dei thread FT puo' ora usare tutti i core logici disponibili fino al nuovo limite `24`, mantenendo comunque il fallback a un solo thread quando la pressione CPU e' severa.
- Aggiunto supporto OpenMP su macOS tramite `libomp` di Homebrew quando disponibile, cosi' il nuovo limite thread e' effettivo anche su Apple Silicon oltre che su Windows e Linux.
- Il percorso di decode embedded passa ora il thread count configurato ai worker FT8, FT4 e FT2 invece di ricadere silenziosamente su un solo worker.
- Aggiunto il plumbing delle opzioni FT8 Stage4 per low-threshold, subpass, cicli, sensibilita' RX-frequency e candidate thinning. Il decode live resta sul profilo stabile, mentre i test offline possono esercitare le strategie Stage4 estese.
- Migliorata la gestione FT8 sulle bande affollate con pass supplementari Stage4, rescue window mirate, scelta focus aware degli overlap e merge piu' rigoroso dei duplicati/frequenze vicine.
- Aggiunte metriche FT8 alternative, incluse equalizzazione tone-power e reverse metric, per recuperare candidati deboli o sovrapposti nei test Stage4 profondi.
- Aggiunto controllo delle iterazioni LDPC nel test harness FT8 e ripristino delle opzioni decoder dopo ogni decode live, evitando contaminazioni tra slot.

### Registrazione RX e diagnostica

- La registrazione WAV RX riceve ora campioni PCM anche dal feed audio legacy, non solo dal percorso spectrum, quindi le registrazioni automatiche restano valide anche se il feed spectrum non e' attivo.
- Aggiunta automazione della registrazione RX tramite variabili ambiente per confronti riproducibili:
  - `DECODIUM_RX_RECORD_SECONDS`
  - `DECODIUM_RX_RECORD_START_DELAY_MS`
  - `DECODIUM_RX_RECORD_ALIGN_PERIOD_MS`
  - `DECODIUM_RX_RECORD_QUIT`
  - `DECODIUM_RX_RECORD_QUIT_DELAY_MS`
- Le metriche FT8 riportano ora opzioni effettive e richieste per threshold/subpass/cicli, insieme ai thread richiesti e attivi.

### Tool di test

- Esteso `ft8_stage_compare` con controlli per opzioni decode, pass supplementari, candidate thinning e iterazioni LDPC.
- Verifica locale completata con build `decodium_qml`, build `ft8_stage_compare` e test Stage4 profondo sullo slot affollato `20260608_014615.wav`.
