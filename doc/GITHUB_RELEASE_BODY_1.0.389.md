# Decodium 4 FT2 1.0.389

Changes from `1.0.387` to `1.0.389`.

## English

### User interface changes inherited from 1.0.388

- Added red-highlight/fade behavior for bypass feedback.
- Cleaned up the DX Cluster dock layout so detaching the cluster no longer leaves residual empty space.
- Improved the DX Cluster detach button readability.
- Added the CQ filter button to the Tx panel.
- Added a process-priority selector in settings.

### FT8 live decode timing

- Reworked the embedded live FT8 decode path so the first visible batch can arrive early while the full/deep pass remains budgeted for the next-slot window.
- Kept the full live FT8 budget capped at about `6.5s` after the slot boundary, matching the intended operating window for deep decode without letting late follow-up work invade too much of the next slot.
- Preserved FT8 slot audio by using a live audio snapshot path even when multithreaded decode is active, avoiding truncated slot captures.
- Re-enabled early FT8 embedded live decode under multithreaded operation, so weak/fast results can appear around the late part of the current slot instead of waiting only for the full pass.
- Applied queue/preemption handling to the multithreaded FT8 branch, so old work is less likely to block current-slot decode output.

### FT8 hash, AP and known-CQ state

- Fixed live known-CQ/hash seeding from Decodium `embedded-ft2/ALL.TXT`; the startup parser now reads `yyMMdd` dates into the correct 20xx year range instead of leaving the cache effectively empty.
- Seeded the FT8 worker hash-call cache before decode so live embedded FT8 can benefit from recently seen calls in the same way as the offline comparison harness.
- Added context filtering for A7 AP hints so previous-slot hints are only reused when they match the current decode context closely enough.
- Reduced AP/CQ/cache hint age to `4` FT8 slots to keep useful warm state while avoiding stale hints that create placeholders or misdirected decode attempts.
- Kept the fix conservative: rejected broader low-threshold/subpass and depth-4 live profiles because they did not recover JTDX-only messages in the WAV benchmark and risked extra late work.

### FT8 benchmark and comparison tooling

- Extended the FT8 stage comparison harness so recorded WAV runs can be evaluated with the same seeded hash/cache state used by live Decodium.
- Improved `tools/compare_alltxt.py` comparison output for the Decodium-vs-JTDX `ALL.TXT` workflow used during this release.
- Verified the current best WAV benchmark on the recorded FT8 window with warm cache state:
  - Decodium unique messages: `324`
  - Common Decodium/JTDX slot+message rows: `274`
  - Remaining JTDX-only rows: `22`
  - Placeholder rows: `9`
- Confirmed that part of the earlier JTDX advantage came from prior hash/memory state: warm seeding recovered messages such as `KD2NZO AO314A` that were missed by a cold Decodium run.
- Confirmed that the remaining gap is not only startup/hash memory: simulated pre-window seeding did not recover all remaining JTDX-only messages.

- Confirmed the full live FT8 pass remains on the intended `6500ms` budget in the edited live path.

## Italiano

### Modifiche interfaccia ereditate dalla 1.0.388

- Aggiunto feedback bypass con evidenza rossa e fade.
- Ripulito il layout dock del DX Cluster: staccando il cluster non resta piu' spazio vuoto residuo.
- Migliorata la leggibilita' del pulsante `Stacca` del DX Cluster.
- Aggiunto il pulsante filtro CQ nel pannello Tx.
- Aggiunto il selettore di priorita' processo nelle impostazioni.

### Timing decode FT8 live

- Riorganizzato il percorso FT8 embedded live in modo che il primo batch possa arrivare early, mentre il pass full/deep resta dentro la finestra consentita nello slot successivo.
- Mantenuto il budget del full live FT8 a circa `6.5s` dopo il bordo slot, cosi' il deep decode puo' completare senza invadere eccessivamente lo slot successivo.
- Preservato l'audio slot FT8 tramite snapshot audio live anche quando il decode multithread e' attivo, evitando catture slot tagliate.
- Riabilitato l'early decode FT8 embedded live con multithreading attivo, cosi' una parte dei risultati puo' apparire verso la fine dello slot invece di attendere solo il full pass.
- Applicata gestione di coda/preemption anche al ramo FT8 multithread, riducendo il rischio che lavori vecchi blocchino l'output dello slot corrente.

### Stato hash, AP e known-CQ FT8

- Corretto il seed live known-CQ/hash dal file Decodium `embedded-ft2/ALL.TXT`: il parser startup ora converte le date `yyMMdd` nel range 20xx corretto invece di lasciare la cache praticamente vuota.
- Il worker FT8 riceve ora il seed della cache hash-call prima del decode, quindi il live embedded puo' sfruttare le call viste di recente come il test harness offline.
- Aggiunto filtro di contesto per gli hint A7 AP, cosi' gli hint degli slot precedenti vengono riusati solo quando sono compatibili con il contesto corrente.
- Ridotta l'eta' utile degli hint AP/CQ/cache a `4` slot FT8: mantiene lo stato warm utile ma limita hint stantii che generano placeholder o tentativi AP fuorvianti.
- Scartate volutamente configurazioni live piu' aggressive con low-threshold/subpass e depth 4, perche' nei WAV non recuperavano JTDX-only e aumentavano il rischio di lavoro tardivo.

### Benchmark FT8 e tool di confronto

- Esteso il test harness FT8 per valutare i WAV registrati con lo stesso stato hash/cache usato dal live Decodium.
- Migliorato `tools/compare_alltxt.py` per il confronto Decodium-vs-JTDX tramite `ALL.TXT`.
- Miglior benchmark WAV corrente sulla finestra FT8 registrata con cache warm:
  - messaggi unici Decodium: `324`
  - righe comuni Decodium/JTDX per slot+messaggio: `274`
  - righe ancora solo JTDX: `22`
  - placeholder: `9`
- Verificato che una parte del vantaggio JTDX veniva davvero da memoria/hash precedente: il seed warm recupera messaggi come `KD2NZO AO314A` che a freddo Decodium perdeva.
- Verificato anche che il gap residuo non e' solo memoria startup/hash: simulare il pre-window seed non recupera tutti i 22 JTDX-only rimasti.
